# cfm behavior gates

model: `claude-haiku-4-5-20251001` · runs per arm: 3

Each probe runs one task twice: **armed** (the skill's text in the
prompt) and **baseline** (the task alone). The delta is the result.
A probe the baseline also passes is VOID, not a win.

| probe | verdict | armed | baseline | note |
|---|---|--:|--:|---|
| glossary | **PASS** | 3/3 | 1/3 | armed 100% vs baseline 33% |
| red-command | **FAIL** | 1/3 | 1/3 | armed 33% vs baseline 33% — the skill's prose did not change the behavior it claims to change |
| seams | **VOID** | 3/3 | 3/3 | the baseline passed too — this probe does not discriminate, so it measures nothing. Sharpen the task or the grader. |
| simplicity | **VOID** | 3/3 | 3/3 | the baseline passed too — this probe does not discriminate, so it measures nothing. Sharpen the task or the grader. |

## What a verdict means

- **PASS** — the armed arm beat the baseline. The prose moved the model.
- **FAIL** — no delta. Either the prose does not carry in a single-shot
  prompt, or this model already resists the behavior.
- **VOID** — the baseline passed too, so the probe is not discriminating
  and proves nothing either way. The model may simply be good at this
  task already, which is a fine reason to retire or sharpen the probe.

## Reading this honestly

**A FAIL is not proof the skill is useless in cfm.** These probes paste
a skill's text into one prompt and grade one reply. That is the weakest
form of every claim, and it is not how cfm uses the text: in the real
workflow the orchestrator enforces ordering through phase gates and a
state file, dispatches the discipline in a scoped brief, and re-runs a
failed gate. A skill can fail here and still hold there. What this
harness rules out is the opposite claim, that the prose alone is
sufficient.

These are measured probe deltas and nothing more. They do not imply a
per-repo figure: the version cfm's agents did not build was never
written, so there is no baseline in a live repo to subtract from.
The graders are text heuristics with stated blind spots (see
`graders.py`); a grader disagreeing with a human read is a grader bug,
so fix it there and add the transcript that fooled it to `fixtures/`.

Run counts this low are noisy. Treat a single run as a smoke test and
raise `--repeat` before drawing a conclusion from any row.
## This run, probe by probe

**glossary — PASS (3/3 vs 1/3).** The real result of the set. A glossary in
the prompt reliably changes what things get named; without it the model
invents `purchases` / `transactions`. This is the claim cfm's dispatch model
leans on hardest, and it holds.

Getting here took two fixes, both bugs in the harness rather than findings:
the grader judged prose as well as code, so a response that correctly said
"I used Order rather than purchase, transaction or basket" was scored as
using the banned words; and `build_prompt` handed the glossary to *both*
arms, so the control was not a control. `tests/run-tests.sh` now asserts
armed-only material never leaks into the baseline.

**red-command — FAIL (1/3 vs 1/3).** An honest negative, and the most
useful row here. Haiku recognises a bug class on sight and leads with it:
one armed response opened "I'll diagnose this following the cfm:diagnose
discipline" and then went straight to "Root Cause: Classic Race Condition".
It had read the rule and broke it in the same breath.

Three rounds of fixes did not move the delta: the probe was replaced (the
first bug was a visible `lines[1:-1]` slice, so both arms were *right* to
skip the repro — that tested the skill outside its stated domain of hard
bugs), the grader was widened twice to accept a test function and then a
bare runnable script, and `skills/diagnose` gained an "Output order — the
one rule" block at the top. The grader fixes lifted both arms 0/3 to 1/3,
which means they were undercounting, not that the skill was working.

Read this as scoping the claim, not refuting the skill: **prose alone does
not enforce ordering.** cfm does not rely on prose for it. `/cfm:diagnose`
is an orchestrator with gated phases and a state file, and the gate is what
refuses to advance. This row is evidence those gates are load-bearing.

**simplicity and seams — VOID (3/3 vs 3/3).** Both arms pass. Haiku already
reaches for `<input type="date">` and already asserts through the public
interface with a literal expected value. The probes do not discriminate, so
they say nothing about the skills either way. Sharpening them needs a
harder over-build trap and a test task with a real seam choice in it; until
then these two rows are unmeasured, not passed.
